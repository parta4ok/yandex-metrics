# Итерации

## Итерация 1: сервер сбора метрик

### Цель

Реализовать HTTP-сервер для сбора и хранения рантайм-метрик. Агент, который
отправляет метрики из пакета `runtime`, будет реализован в следующей итерации.

### Запуск сервера

- Адрес: `http://localhost:8080`.
- Редиректы не поддерживаются.

### Поддерживаемые метрики

| Тип | Значение | Правило обновления |
| --- | --- | --- |
| `gauge` | `float64` | Новое значение замещает предыдущее. |
| `counter` | `int64` | Новое значение прибавляется к предыдущему. |

Сервер должен принимать и хранить метрики произвольных имён этих типов.

### HTTP API

#### Обновление метрики

```text
POST /update/<ТИП_МЕТРИКИ>/<ИМЯ_МЕТРИКИ>/<ЗНАЧЕНИЕ_МЕТРИКИ>
Content-Type: text/plain
```

| Условие | Ответ |
| --- | --- |
| Метрика принята | `200 OK` |
| Имя метрики отсутствует | `404 Not Found` |
| Тип метрики или её значение некорректны | `400 Bad Request` |

#### Пример запроса

```http
POST /update/counter/someMetric/527 HTTP/1.1
Host: localhost:8080
Content-Length: 0
Content-Type: text/plain
```

#### Пример ответа

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
```

### Хранение

- Объявить тип `MemStorage` для хранения метрик.
- Использовать `struct` с полем-коллекцией (`map` или `slice`).
- Описать интерфейс взаимодействия с хранилищем.
- Структура хранилища должна позволять без изменения публичного контракта
  добавить поля в следующих итерациях, например логгер или мьютекс.
